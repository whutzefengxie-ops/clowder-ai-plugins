# 反馈插件实施与验证

用户授权：2026-10-28“按照方案，拉 workTree 进行落地实施，然后提 PR”。此前修订的自动提交、手动兜底、字段旁复制、实际图片交付、流程进度和实际 Issue 链接均保留。

业务实现位于 `packages/feedback`；宿主配套分支 `feat/feedback-host`。复用现有 UI command/slot-item 声明，无需更改 manifest schema。该候选包尚未加入发布目录、初装列表或生产 runtime。

## 当前实现

- 一个底部侧栏入口，四步面板；不增加主界面内容。
- 直接反馈与已配置 Client 诊断；诊断前展示确定性脱敏材料与 Client/模型，截图不进入模型。
- 版本化排查配方，输出事实、推测、证据缺口及未验证事项；模型输出再次过滤。
- 可编辑预览、字段旁文字复制、每张截图 PNG 复制和原图下载。
- GitHub/GitLab REST 与组织 JSON CLI 分离于业务状态机；内网不会调用公网兜底。
- 自动上传确认绑定目标配置、报告和图片；上传前 CAS 持久化，未知结果只核对。
- 自动提交返回平台实际链接，并回读中文标题、正文、提交标记；附件回读 SHA-256。
- 手动跳转不携带标题或正文，不记录为已发布。

## 已运行的验证

- 插件 TypeScript 构建通过；9 项业务、脱敏和 Provider 测试通过。
- CI gate 编排的 12 项测试通过，新插件检查已加入现有入口。
- 使用 Node 24.18.0 / npm 11.16.0 打包，零运行时依赖；清洁目录 npm 安装后加载实际入口。
- 配套宿主的真实 React 入口、opaque iframe、owner HTTP route 与模块调用端口联合运行，10 项浏览器检查通过：复制文字、图片 PNG 编码、原图下载、手动弹窗且不建单、实际图片字节上传/回读、自动结果 URL、分析前/后脱敏和窄屏。
- 宿主有独立的 owner/生命周期/日志边界测试和原生调用参数测试；后者先观察私有 L0 canary 失败，再验证关闭私有上下文、工具及会话持久化。

浏览器检查使用合成日志、测试凭据、合成 Client 和远端替身。它证明跨仓接线与实际打包字节，不证明真实账号、云端模型或内网平台写入验收。未创建真实反馈 Issue。

完整 `gate:ci` 在本机 Windows 的既有 toolchain 检查中遇到 `spawnSync npm ENOENT`（npm 为 `.cmd`，脚本使用无 shell 的 `execFileSync('npm')`）。没有为绕过检查改动检查器；Linux CI 仍须回读。真实安装设置页、模型与企业附件通路是上线前验收边界，PR 不视为发布。
