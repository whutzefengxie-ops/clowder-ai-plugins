Implementation comparison

流程下面的交付与基线，
不再像另一套旧界面。

同一份 demo 数据，同一个同步中状态。只改流程 rail 以下：本笔交付、上游/内部 PR、Issue 摘要、内外基线、技术详情入口和撤销区域。

1 · 本笔交付：从裸链接 / 指标块到 V3 交付卡

优化前BEFORE
优化后AFTER
结构化
  • 「本笔交付」标题 + 上游 / 内部 PR 两个独立胶囊
  • 内部 PR 未创建时用琥珀色 pending，不再和链接混排
  • 4 个指标做成卡片；Issue 直接显示标题
更少滚动
  • 撤销表单默认收起，只保留危险入口摘要
  • 「关联 Issue / 本笔提交」卡片高度收紧
  • 同一屏能同时看到交付、Issue 和基线

2 · 内外基线与技术详情：从折叠标签到可见基线

优化前BEFORE
优化后AFTER
先看结论
  • 外部 base → target、内部 base → accepted 直接可见
  • 完整 SHA 保留在 title / 展开的「查看内外基线与提交位置」里
  • 技术详情仍是折叠项，不抢占主视线
V3 对齐
  • 标题不再被旧 CSS 隐藏
  • 基线段与交付卡使用同一套边框、圆角和字号
  • 展开 / 收起按钮和状态提示同排，不再散落

4 · 左侧栏项目状态：合并进项目行

优化前 · 独立面板BEFORE
优化后 · 行内状态AFTER
不再拆分
  • 移除「查看项目状态」独立折叠面板和筛选按钮
  • 状态点、模式、最后接收与观察日期直接放进项目行

5 · 同步记录：筛选上移，每页最多 10 笔

优化后 · 记录页AFTER
筛选在页首
  • 搜索、状态、日期快捷与自定义范围移到记录页顶部
  • 「筛选记录」和匹配数量放在同一行，列表不再承担筛选
  • 顶部筛选与下方 320px 记录列分离，主区域更安静
每页 10 笔
  • 列表请求 `limit=10`，翻页步长改为 10
  • 列表底部显示「每页最多 10 笔」
  • 记录再多也只占一页高度，不再把页面拉得很长
