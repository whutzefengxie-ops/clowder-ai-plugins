# 仓库连接、Issue 认证与首次关单规则确认

继续 PR #77。用户实际使用反馈：两侧字段错列；CodeHub 被迫填写 GitLab API 项目 ID 与环境变量；提交消息关单确认没有可理解的操作。

## 用户旅程与实现边界

- 连接页使用两列独立仓库分组：外部地址 / 交付分支；内部地址 / 合入分支 / 网页地址。移动端以完整分组顺序排列，不能把两个仓库字段交错。
- Git 认证与平台 API 认证分别说明。用户随后在 [#77 的测试评论](https://github.com/zts212653/clowder-ai-plugins/pull/77#issuecomment-6165865422) 提供了实际 CodeHub 证据：GitLab v4 API 创建可用，所用 Git push-options 不创建 MR，网页与 API 不同域，Node 需企业 CA，MR 使用无 `/-/` 的旧地址。采纳协议与错误发现，不把基础创建当成完整同步验收，也不复制内部项目 ID、域名或账号。
- 新增内置 `pullRequests.mode=gitlab`，与 Issue 共用 API 项目及认证。Git 负责候选传输，平台接口查询 / 创建 / 回读 MR，沿用原创建意图、稳定交付标识与 head/base 保护；未知结果不再次创建，不自动合入。旧 Git 意图不被改选 API 静默重置。
- GitLab 兼容方式可填写 Issue 网页链接，生成项目路径与 API 地址建议，无须寻找数字项目 ID；高级选项可修正。不是任意平台接口自动发现，子路径部署及其他协议不猜测。
- Token 支持密码框直接输入，单独受会话令牌 / Origin / 项目 / 配置版本保护的接口接收；仅存在当前服务内存，不进入配置、任务、历史、URL、日志、浏览器草稿或安装制品。环境变量保留为已有配置与高级用法。服务重启需重新输入；提交 Token 不等于 API 验证。
- 移除连接步骤中的关单勾选项，在首次准备同步的同一流程内展示：外部 `Closes #123` 可能影响内部同号 Issue；给出隔离测试仓的推送与合入核对步骤。未确认时不能发布候选。确认可在已有基线后单独保存，不改模式 / 文件规则 / 接受游标，并记录配置观察。

## 验证

### 用户补充后的最终规则

- 主区域推荐填写 Issue 网页链接及 Token，实时展示同域 API 与项目路径的推断结果；API 地址与项目 ID / 路径标为可选，默认折叠在高级设置内，独立 API 域名 / 特殊部署时显式覆盖。Token 变量只在环境方式必填。
- 原 `INVALID_ISSUE_CONFIG` 合并多项检查且丢失字段信息。现在用固定字段 / 原因白名单定位当前提交的表单，展开错误区域、聚焦输入框、保留普通草稿；不返回 Token、输入值或原始异常。末尾 `/` 和 `%2F` 项目路径可规范化；旧合法配置的表示与绑定身份保留。隐藏共享设置时保留既有 API 域名。
- 接管已有仓库时 U0 保持历史已接收版本，I0 使用内部当前 HEAD；旧 I0 错误定位到字段。读取自动填当前 I0 并保留 U0，不修改内仓。专项路径保留、核心一致与历史保护仍生效。
- 按用户最新范围决定，移除三方文件合并、在线冲突编辑及执行模块。两种模式均只支持完整内部保留路径，其余核心严格一致；区别仅在 tag 单笔交付与逐 PR 过程交付。旧非空 `mergePaths` 明确拒绝并保留配置 / 台账，不能静默迁移；历史旧规则仍可作为只读证据显示。
- 对应回归含错误 RED、字段与安全序列化、仅链接配置、高级覆盖、基线重读、真实 Git 专项保留、二进制精确保留、原对象恢复、旧配置不改写及安装包不含已移除模块。

先观察字段分组、人工模式隐藏字段、密码草稿泄露、缺少凭据入口及已有基线无法保存确认的 RED。HTTP 验证 Token 只在内存使用，不能跨项目复用、旧配置拒绝、清除 / 服务停止失效，不返回 Token，API 校验只读不建单。真实浏览器覆盖模式切换、Token 输入、草稿 / 刷新 / 多项目、当前步骤确认与 1440 / 390 排版，再跑相关及全量回归。
