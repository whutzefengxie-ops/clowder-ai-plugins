# 仓库同步插件：用户旅程优化方案（待审）

本方案供用户审核。**本次只新增方案文档并更新原 PR #77；界面、服务、认证和同步行为均未按本方案修改。审核通过后，在同一个分支、同一个 PR 内完整实施。**

目标是让用户进入一个项目后，能回答三个问题：目前同步到哪里、现在由谁处理、下一步在哪里操作。首次配置说明白，正常同步少操作，异常恢复有依据。

## 1. 分析依据与结论

输入是用户提供的《repo-sync-plugin-ux-review》及此前已确定的产品约束。对照代码基线为 `c42a4f4d7ceaba5f37c81999eacb633fa2cc6643`，现有 [PR #77](https://github.com/zts212653/clowder-ai-plugins/pull/77) 保持 Draft。本轮只读查看了正式入口的未配置页面；已配置、后台与异常路径的判断来自当前源码，尚未通过本轮真实内网操作重新验证。

总体判断：**建议对“用户不知道该做什么”的诊断成立，但部分现状描述已经过时，部分解决方法会引入新的风险或复杂度。应改进现有旅程，而不是叠加另一套向导、仪表板、日志窗口和通知中心。**

| 审查中的描述 | 当前实现依据 | 对方案的影响 |
|---|---|---|
| 刷新页面会丢失全部 Token | `src/github-auth.mjs`、`src/issue-auth.mjs` 将直接输入的 Token 存在服务进程内存中，页面刷新和关闭不清除；服务重启才丢失 | 改正生命周期说明，增加认证状态与恢复入口，不把密钥改存浏览器 |
| 没有 Token 检查 | 已有 `/api/github-check`、`/api/issue-check` 及只读验证按钮 | 集中到初始配置，说明具体验证范围，不能用一次读取证明所有写权限 |
| 没有文件树，必须填路径 | `web/files.mjs`、`file-rules.mjs` 已有树、目录继承、半选、搜索及分页；但入口依赖核验失败后出现 | 改善出现时机、可发现性和影响预览，不重复造树 |
| 没有步骤进展、执行记录或恢复 | `workflow.mjs`、`attempts.mjs`、`operations.mjs` 已有阶段、子步骤、时间与原请求恢复；部分视图重复 | 合并用户可见的步骤与证据，保留底层恢复机制 |
| 没有历史筛选与多项目 | `history.mjs` 已有搜索、状态、日期和分页；`projects.mjs` 已有项目隔离与草稿保存 | 优化查找、状态概览与跳转，避免为已有功能另建入口 |

报告中的示例代码、2024 年日期、工期、评分及“满意度提升 50–80%”均不作为验证结果。Node 测试通过不等于真实内网平台、所有操作系统和首次使用体验已验收。

## 2. 建议逐项取舍

“已有需优化”仍属于本次实施范围；“暂不采纳”不进入此次交付。以下覆盖原文 10 类建议、快速改进清单及创新附录。

| 编号 / 建议 | 决定 | 理由与具体处理 |
|---|---|---|
| 1a 快速开始与高级向导 | 调整采纳 | 只有一套三步配置，必要项直接展示、高级项就地折叠。两个向导容易产生行为差异和维护分叉 |
| 1b 模式对比、术语解释 | 采纳 | 用用户目标解释两种模式，U0/I0 放在辅助信息；说明可点击、可键盘访问，不只依赖悬停 |
| 1c 默认推荐新手使用版本模式 | 不采纳 | 模式取决于是否需要搬运开发过程，不能按熟练程度替用户选择；保留已有选择，新项目明确选择 |
| 1d 自动检测历史基线 | 调整采纳 | 自动读取内部当前 HEAD；外部历史起点只从当前绑定的可信接收台账推荐，缺证据时由用户提供。不能把外部最新 main 当作上次已同步版本 |
| 1e 文档、配置等预设规则 | 调整采纳 | 提供“查找 README / 文档差异”等筛选入口，列出真实路径供选择；不一键写入 `*.md`、`.env*` 等通配规则 |
| 1f 从 `.gitignore` / 文件类型推断内部专属内容 | 不采纳 | Git 忽略规则、文件扩展名不能证明已提交文件的归属；误保留会漏掉外部修复 |
| 1g 随时返回修改、草稿保护 | 调整采纳 | 启用前可返回，普通字段和选择保留；启用后沿用已冻结绑定，不能通过返回按钮改写基线和历史 |
| 2a 初始集中认证、测试连接、获取 Token 帮助 | 已有需优化 | 将代码访问、来源元数据、内部对象接口分清，在配置时完成；只读检查自动串联，无需用户在后续步骤寻找认证入口 |
| 2b 默认 sessionStorage / localStorage 记住 Token | 不采纳 | 当前后台由服务持有，浏览器存储不能解决服务重启恢复，还新增密钥副本；保留服务内存与已有环境变量方式 |
| 2c 本地主密码加密保存 | 暂不采纳 | 会新增密钥保管、解锁和多项目生命周期；不纳入本次 UX 调整。长期无人值守沿用已有环境变量配置 |
| 2d 实时验证、到期和配额提示 | 调整采纳 | 提供后或主动点击时检查，不逐字符请求；仅展示平台实际返回的到期、限流信息，未知明确显示未知 |
| 3a 友好错误标题、原因、具体操作、详情折叠 | 采纳 | 错误就地归属字段或失败子步骤，包含事实、影响和可执行的下一步；原因区分已证实与待排查 |
| 3b 一键重新设置基线 / 自动修复差异 | 不采纳 | 会掩盖来源和内容问题，破坏已接受版本的证据。启用前修改原输入后重验；启用后通过原交付恢复或内部修复 PR 处理 |
| 3c 差异弹窗、报告问题 | 调整采纳 | 差异在当前步骤内查看；提供复制脱敏诊断摘要，用户预览后自行报告，不自动上传日志、配置或内部对象信息 |
| 4a 全景进度、当前项/总数、执行证据 | 已有需优化 | 统一阶段与子步骤，明确本轮、本笔和当前 Git 阶段，完成后折叠；证据跟随步骤，不另开日志窗口 |
| 4b 全局百分比、按历史速度推算 ETA | 调整采纳 | 展示已核验完成笔数 / 冻结总笔数；Git 有真实进度才显示阶段百分比。人工审核和未知网络耗时不显示倒计时或虚构全局百分比 |
| 4c 取消、暂停、最小化后台 | 调整采纳 | 区分取消可取消的读取、停止后续自动处理、已发布对象保留；不承诺撤销远端写入。关闭页面继续由服务处理，无系统托盘概念 |
| 4d WebSocket 替换轮询 | 暂不采纳 | 通信协议不是当前用户阻塞的根因。先测量并优化现有轮询，不引入第二套任务状态通道 |
| 5a 文件树、差异标记、并排内容和规则影响 | 已有需优化 | 提前展示入口，明确保留内部的完整路径、继承和未来文件覆盖；同一面板预览，不以大文本框为主入口 |
| 5b AI 推荐保留并一键应用 | 不采纳 | 文件归属是用户决定，不能凭“95% 置信度”跳过核心代码；不向 Agent 发送内部代码或引入模型依赖 |
| 6a 项目概览、状态筛选、配置健康提示 | 采纳 | 做轻量项目列表，展示本地台账可证明的状态、最后观测时间和一个入口；不把过期观测叫作实时健康 |
| 6b 每次切换都提示未保存 | 调整采纳 | 普通草稿已按项目保存时只提示保存结果；草稿保存失败或存在未提交密钥时才提示，避免频繁确认 |
| 6c 批量检查、批量同步、项目分组 | 暂不采纳 | 本次先保障每个项目可独立配置、同步与恢复。批量远端操作、分组不是修复当前主旅程的必要条件，需另行确认调度与权限边界 |
| 7a 历史搜索、状态/日期快捷筛选 | 已有需优化 | 保留现有能力，增加日期快捷项和清楚的空状态；选中即在同一流程回看当时信息 |
| 7b 自定义条件编辑器、筛选书签、三种历史视图 | 暂不采纳 | 增加入口和学习成本；当前搜索、状态和日期先满足实际查询，不引入通用报表系统 |
| 7c CSV / JSON 导出 | 暂不采纳 | 结构化导出容易把内部路径和配置带出；本次先做好只读历史和脱敏摘要，完整导出需单独设计字段与用途 |
| 8a 窄屏、44px 触控区域、键盘和焦点可见 | 采纳 | 保证配置、文件选择和主操作在窄屏可达，宽屏仍为主要操作场景 |
| 8b 底部导航、左右滑动重试、紧凑模式 | 暂不采纳 | 保持现有导航，使用可见按钮；手势不能成为执行同步或恢复写入的隐蔽入口，紧凑模式增加配置负担 |
| 9a 需要处理 / 完成提示 | 调整采纳 | 在项目列表和当前流程内显示，不重复刷提示。浏览器外通知不属于本轮必要路径 |
| 9b 通知中心、邮件、Webhook、企微/钉钉、多用户实时协作 | 暂不采纳 | 会扩张为消息、账户和协作产品；当前是本地操作工作台，PR 审核继续由内部平台承担 |
| 10a 加载反馈、按需读取、缓存与性能优化 | 调整采纳 | 沿用现有原生模块、历史分页和缓存，按测量优化；活动记录不得被历史缓存覆盖 |
| 10b React lazy、查询库、全面虚拟滚动、离线缓存 | 暂不采纳 | 当前没有 React 栈；先解决具体瓶颈，不为了实现示例更换框架。离线不能证明已同步或执行远端写入 |
| 附录：冲突预测 / 在线手动合并 | 不采纳 | 用户已明确不引入三方合并。做确定性的差异与投影检查，不能宣称 AI 预测“安全”，也不提供在线代码合并器 |
| 附录：Dry-run 影响预览 | 调整采纳 | 增加可选的只读“预览同步范围”，复用真实扫描和文件规则；不成为每笔必点步骤，不创建对象或运行任意项目命令 |
| 附录：同步关系图谱 | 调整采纳 | 先用本笔记录中的“外部对象 → 内部对象”对应表表达；不新增完整分支图、依赖图和独立图谱导航 |
| 清单：按钮层次、状态、加载、微动画、撤销 | 调整采纳 | 统一主操作和状态文字，加载不留空；尊重减少动画设置。只有已有可逆边界才显示撤销，不承诺撤回已合入代码 |
| 路线图、ROI、可用性测试 | 调整采纳 | 采纳无提示任务测试；不承诺示例工期、满意度百分比或“10 分钟完成同步”，外部下载与人工审核耗时需分开记录 |

## 3. 页面结构与完整用户旅程

### 3.1 入口：先选项目，再做当前任务

顶部固定呈现当前项目名称、同步模式和两侧仓库标识。项目切换入口可展开轻量列表：项目名、配置状态、当前同步状态、最后接收版本、最后检查时间和“进入项目 / 处理异常”。支持“全部 / 需要处理 / 运行中”筛选。

单项目不强迫经过总览；返回项目恢复原位置。项目列表读取本地状态，不在打开页面时偷偷扫描所有远端。不读取或展示其他项目的 Token。不增加独立“执行记录”导航。

### 3.2 首次配置：保留一条三步路线

```text
1 连接与认证 → 2 核验已有同步起点 → 3 确认启用
  当前步骤展开；完成步骤显示摘要，可在启用前返回修改
```

**第一步：连接与认证。** 先用两张选择卡说明模式；不选择则不能继续。

| 模式 | 用户要达到的结果 | 必需能力 |
|---|---|---|
| 按版本更新 | 选 tag，保留内部文件，生成一个内部同步 PR | Git 访问和已配置的 PR 自动创建通道；不搬运来源 Issue |
| 同步开发过程 | 选终点 tag / commit / 扫描时最新版本，逐笔同步 PR 或直接主干提交、Issue 和提交映射 | Git、GitHub 元数据读取、内部 Issue 创建/关联/关单、内部 PR 创建 |

两侧并排、窄屏上下排列，字段始终归属对应仓库：

- 外部：GitHub 地址、交付分支；过程模式显示 GitHub 读取 Token。
- 内部：Git 地址、合入分支、对象网页入口、PR 自动创建方式；使用平台 API 时显示内部 Token。
- 可推导：填写 Issue 页面或仓库网页入口后，显示推导出的仓库首页、API 基址与项目路径及“由哪个输入推导”。两者冲突时就地报错；推导失败才展开对应覆盖项。推导不等于平台协议兼容验证。
- 高级项：独立 API 域名、项目 ID/路径覆盖、环境变量认证、已有私有适配器参数、提交身份细节。每项标明“必填 / 当前方式必填 / 自动推导 / 可选覆盖”，不隐藏错误字段。
- 提交身份：直接显示“保留上游身份”或“统一内部身份”的选择及 SHA 影响；姓名邮箱细节折叠在其下。用户选择重写时展开必填字段。

主按钮为“保存并检查连接”。先校验普通字段，再绑定配置和提供密钥；只读检查在按钮下逐项显示。保存成功但认证失败，明确显示“仓库已保存，认证待处理”，回到失败项继续，不重建项目，不要求重填整张表。普通字段错误不清除服务中已有认证，未提交密钥不写草稿。

检查内容按实际能力显示：Git 是否可读取两侧 ref、GitHub 必需读取是否成功、内部接口是否可读。**只读检查不证明 Git 推送、创建 PR 或关闭 Issue 必定成功。** 对未能验证的写能力标注“实际执行时核验”，不能显示“全部权限通过”。已有人工创建配置明确标为“人工兼容方式”，不承诺配置后全自动，也不自动降级为人工。

过程模式的“提交消息不会误关 Issue”改为一个有解释的一次性接收条件：用外部 `Closes #123` 与内部同号 Issue 举例，给出独立测试仓验证方法、可记录的验证结果以及管理员配置路径说明。未确认时明确阻塞首次发布的原因和处理入口；不能用 API 读取成功或一个无说明的复选框替代验证。

**第二步：核验已有同步起点。** 前一步收成简短摘要；按钮执行后自动定位当前标题，核验状态和错误均显示在本步。名称改为：

| 主标签 | 辅助信息 | 填写方式 |
|---|---|---|
| 上次已经接收的外部版本 | U0；历史起点，不是本次目标 | 输入历史 tag 或完整 SHA，解析并展示准确 SHA；仅有可信既有台账时可推荐 |
| 内部当前接收位置 | I0；当前合入分支 HEAD | 读取并填入，显示分支、完整 SHA 和读取时间；提交前再次防止过期 |

例如外部从 A 又增加 20 个提交，内部在 A 之后有文档专项改动：U0 仍是 A，I0 是内部当前 main。核对的是 I0 与 A 的核心文件，不是要求内部先等同外部最新版本。此步骤只登记对应，不自动修改内部 main。

本步提供“查看两侧文件与保留范围”，即使核验成功也可查看；发现差异则直接展开。文件树、内容查看、选择摘要和“应用选择并重新核验”在同一块区域。核心差异清零且基线有效后才能继续。

**第三步：确认启用。** 汇总两侧仓库/分支、模式、U0 ↔ I0、保留路径、身份策略、对象自动化能力、认证状态及检查范围。一个“启用并进入同步工作台”按钮，启用本身不推送或创建对象。已有绑定不重复登记，下一次直接进入当前任务。

### 3.3 日常同步：一个意图，自动执行到待审核

进入项目先看到“已接收版本 / 本轮目标 / 当前状态 / 下一步”。过程模式选择 tag、commit 或最新分支快照，点击“开始同步”；版本模式选 tag，点击“同步到所选版本”。已有有效认证和接收条件时，不再手动点击准备、创建 Issue、创建 PR、核验、关单。

目标名称与解析后的 SHA 同时展示；“最新”仅针对上次成功检查的上游分支，显示检查时间。指定终点达成只标“已到达本轮目标”，不能因此宣布整个仓库已是最新。过程模式继续遵守主干祖先关系和完整 PR 边界；明确无关联 PR 的主干提交自动纳入，来源不明才暂停。

```text
① 读取范围与来源
  ├─ 解析 tag / commit、冻结目标
  ├─ 核对历史前进关系和 PR 边界
  └─ 列出来源 PR / 直接主干提交与 Issue
② 准备本笔
  ├─ 创建或复用内部 Issue（仅过程模式）
  ├─ 准备提交、应用内部保留范围、保存 SHA 映射
  └─ 执行实际配置的检查
③ 发布并创建 PR
  ├─ 保存发布意图、推送候选、回读 ref
  ├─ 自动创建或确认原内部 PR
  └─ 关联并回读内部 Issue（仅过程模式）
④ 等待你在内部平台审核合入  → 打开具体内部 PR
⑤ 自动核验与保存结果
  ├─ 核验实际合入结果、核心文件与历史
  ├─ 核验所需提交、更新应关闭 Issue 并回读（仅过程模式）
  └─ 保存接收记录；过程模式继续下一笔，直至冻结终点
```

已有真实子步骤为进度真相源，用户可见路线与它对应。一个子步骤只显示一行状态；开始/结束时间、对象和每次尝试收在该行下，避免上方一套步骤、下方又一套重复执行清单。扫描尚未得到完整集合时不显示虚假的总数。

**完成阶段自动折叠，当前及失败阶段默认展开；用户主动展开的阶段不会被轮询收起。** 不强制滚动打断用户阅读历史；用户发起操作后定位当前步骤，后台变化只更新状态和“回到当前步骤”入口。

### 3.4 每种状态都有明确的主操作

主操作由同一策略计算，当前任务区只显示一个强调按钮；需要固定操作条时承载同一按钮，不在顶部、步骤内、页底并列重复。只读链接和停止操作使用次级样式。

| 当前状态 | 主操作 / 系统提示 | 后续行为 |
|---|---|---|
| 未配置 / 配置草稿 | 继续配置 | 进入未完成步骤，保留本项目普通草稿 |
| 认证缺失或失效 | 补充对应认证 | 在当前失败位置展开对应输入，提供后回读原状态 |
| 未完成接收起点核验 | 核验已有同步起点 | 差异和处理在本步，不跳页找错误 |
| 可开始 | 开始同步 / 同步到所选版本 | 提交一个同步意图，目标冻结 |
| 自动运行 | 正在执行：具体子步骤 | 不提供可重复发起的按钮；次级入口查看证据或停止后续 |
| 等待审核 | 打开内部 PR ↗ | 跳到具体平台地址；说明合入后自动继续，后台检查失败时另示异常 |
| 已合入待元数据 | 正在核验与更新 Issue | 自动继续；失败只恢复原 Issue / 记录，不重推代码 |
| 写入结果不明 | 回读原 PR / Issue 操作 | 核对稳定标识及原对象；不能直接点击“再创建一个” |
| 执行记录保存失败 | 补存原执行记录 | 明确业务动作可能已成功，只修记录 |
| 已暂停 | 恢复原轮次 | 维持冻结终点、候选和对象；恢复前核对前置条件 |
| 本轮完成 | 选择下次目标 | 保留本轮摘要和历史入口；最新状态有时间依据 |
| 正在查看历史 | 返回当前同步 | 全部动作只读，不出现重试、重新创建或关单按钮 |

### 3.5 失败就在原处解决

统一错误卡片固定包含：**发生了什么 → 哪一步没完成 → 已完成内容是否保留 → 下一步操作**。错误码、任务标识和安全诊断可展开复制；不直接呈现原始命令、stderr 或密钥。未知错误如实说“原因尚未确认”，不猜测有人绕过流程改了 main。

| 场景 | 就地提示与动作 | 继续执行的边界 |
|---|---|---|
| 普通字段不合法 / 自动推导冲突 | 标记具体字段、展开所在区域、定位首个错误 | 原配置和认证保留；只修相关字段 |
| Git 凭据、GitHub Token、内部 Token 失败 | 明确是哪个通道，展示该通道的检查或补充入口 | 不建议换无关 Token，不把 Git 登录说成 API 登录 |
| 初始文件差异 | 展示文件树、两侧内容、保留规则与未处理差异数 | 用户明确保留，或在内部修复核心内容后重验；不自动覆盖 |
| 已启用后核心文件漂移 | 显示当前 HEAD、期望范围、具体差异及内部修复 PR 指引 | 不重新设置基线跳过；原交付和规则保留 |
| 目标不前进、tag 移动、PR 边界不完整 | 显示基线和解析目标、关系失败点 | 修改尚未发起的目标；已有轮次不能静默换终点 |
| 无关联 PR / 来源读取失败 | 前者标明直接主干提交并继续；后者显示失败读取项 | 读取失败不能降格成“无 PR”而跳过核验 |
| 网络中断、限流、状态过期 | 显示最近可靠状态和观测时间，自动回读原任务；有限流信息才显示等待窗口 | 不重送新的同步请求，不显示虚假完成 |
| PR / Issue 创建回执不明 | 展示原意图及查询结果；必要时补登记核对后的原对象引用 | 查询确认前不再创建同类对象 |
| 内部 PR 未合入 / 被关闭 / 合入分支改变 | 区分真实对象状态、Git 合入证据和观测错误 | 不把关闭当作合入，不伪造成功或自动重新创建 |
| 代码已接受但 Issue 关单失败 | 显示“代码已接收，Issue 待处理”，展开所缺关联或提交条件 | 恢复原关单操作；普通关联不关闭，跨笔所需提交未齐不提前关闭 |
| 服务重启、浏览器刷新、项目切换 | 从台账回到原任务；仅缺失认证时提示补充 | 浏览器关闭不停止服务任务；服务重启后需凭据才能继续远端操作 |
| 台账或执行记录保存失败 | 区分业务动作结果与记录保存结果 | 恢复原记录，不借重试再推送、建单或合入 |

停止功能按当前实际边界提供。只读可取消步骤显示“取消本次读取”；已发出远端写入时说明“等待结果确认”，保留原对象。暂停自动继续显示“停止后续处理”，不能叫作回滚。不会增加三方合并或自动修复核心代码。

### 3.6 文件保留与只读范围预览

文件树使用“保留内部”，不使用含糊的“忽略错误”。勾选表示整个路径都跳过外部更新，包括外部修改、删除及目录下未来新增文件；未勾选的核心范围严格跟随外部。目录继承、半选、搜索和分页遵循现有规则，页面外未加载的选择也要保留。

README 反转示例：外部 `README.md` 是英文、`README.cn.md` 是中文；内部 `README.md` 是中文、`README.en.md` 是英文。用户可明确保留这三个路径，包含“内部目前不存在”的 `README.cn.md`，从而避免外部文件被重新引入；其余代码继续同步。**这是整文件保留，不做自动改名或语言内容映射；这些路径的外部更新也不会自动进入。** 不存在路径仍保留显式高级入口，并在树旁展示规则摘要。

树旁影响预览区分“将保留内部的路径 / 将跟随外部变化 / 仍阻断核验的核心差异”，统计标明是完整结果还是当前页。勾选后先更新草稿预览；保存并重验成功才登记有效基线。启用后规则保持冻结；查看原选择不等于允许随时扩大忽略范围。

可选“预览同步范围”显示解析目标、实际来源集合、预计对象数量、文件增删改和保留路径命中。只读含义是**不推送、不创建/关联/关闭远端对象、不改变已接受版本**；允许必要的本地 Git 下载缓存。数据不完整就标明未完成，不能预先编造内部 PR 编号、耗时或写权限结论。真正同步仍重新核对目标、配置和内部 HEAD，过期预览不能直接放行。

### 3.7 历史回看与进展数值

历史保留现有列表与筛选，新增最近 7/30/90 天快捷项、清楚的匹配数量及空状态。选记录后复用同一条五阶段流程，展示当时目标 tag/SHA、内外基线、候选与实际合入 SHA、保留规则、身份策略、Issue/PR 对应、步骤时间与每次尝试。缺少的旧信息显示“未记录”，不用当前配置补齐。

对象对应采用表格：“外部 PR / 主干提交 → 内部 PR”“外部 SHA → 内部 SHA”“外部 Issue → 内部 Issue”。区分原始提交、重写提交、工具接收节点和平台合入节点；只显示实际存在的类别与数量，避免把提交数不等直接说成同步异常。

全景摘要使用“本轮已核验完成 3 / 8 笔；本笔等待审核”，不是“已创建 3 个 PR 所以完成 3 笔”。未知总数时写正在读取；失败、未开始和人工等待不算已完成。当前 Git 阶段有真实百分比时可显示，未提供进度时显示耗时和最近活动，不推算人工审核 ETA。

## 4. 实施契约与改动位置（审核通过后生效）

沿用 [自动同步约定](2026-10-15-repo-sync-automatic-operator-journey.md)、[双模式与对象映射](2026-10-14-repo-sync-continuous-target-and-issues.md) 和 [既有用户旅程方案](2026-10-14-repo-sync-user-journey-optimization.md)。冲突时以本次用户审核后的取舍为 UX 增量，不能借页面简化扩大写入权限。

Architecture cell：浏览器负责输入与展示，正式服务负责认证、任务、后台观察，原台账负责可恢复事实。Map delta：不新增同步引擎、外发通道、Agent、浏览器密钥存储或另一套持久状态；项目列表可增加脱敏的本地状态投影，配置页可增加历史 tag 解析与只读预览接口。Why：用现有能力完成清楚的旅程，避免“看起来完成”和“实际已接受”成为两个真相源。

| 工作单元，按依赖顺序 | 主要改动位置（均为 `packages/repo-sync/` 下） | 可观察产物 |
|---|---|---|
| A：统一下一步与状态文字 | `web/action-policy.mjs`、`automation-view.mjs`、`actionbar.mjs`、`workbench.mjs` | 同一事实只投影一个主操作，明确本轮/本笔/观测状态 |
| B：三步配置与认证 | `web/connections.mjs`、`repository-fields.mjs`、`issue-settings.mjs`、`github-auth.mjs`、`issue-auth.mjs`、`form-errors.mjs`；对应 `src/*auth-http.mjs` 与连接处理模块 | 必要项可见、推导结果明确、认证就地检查、历史 tag 解析、部分成功可续接 |
| C：步骤、错误与文件树合一 | `web/workflow.mjs`、`attempts.mjs`、`operations.mjs`、`diagnostics.mjs`、`file-rules.mjs`、`files.mjs`、`stage-facts.mjs` | 原处看到具体步骤、差异、时间和恢复动作；预览复用真实检查 |
| D：项目列表与历史回看 | `web/project-view.mjs`、`projects.mjs`、`history.mjs`、`src/server-projects.mjs`、`records.mjs` | 多项目状态可找、记录可查；信息按原绑定归属，历史全只读 |
| E：布局与操作一致性 | `web/styles.css`、现有流程/文件树样式及 `web/app.mjs` | 主操作可达、长地址不挤坏布局、错误焦点可见，轮询不抢输入 |
| F：旅程验证、使用说明与正式入口 | 对应 `test/`、`README.md`、验证记录 | 完整旅程证据、适用边界与同一 PR 的交付说明 |

上述是内部实施顺序，不拆分 PR，不先交一个新的演示页面。正式服务保留现有配置、项目注册表、台账和历史；不因 UX 修改要求重新初始化用户数据。

必须保持的状态约束：

1. 页面主操作来自同一份项目状态；历史选择、草稿和展开状态不能成为同步游标或写入许可。
2. 配置与认证绑定项目、仓库及修订；切换项目后旧检查响应、旧表单和旧 Token 不得作用于新项目。
3. 直接输入的 Token 只在服务内存；非密钥草稿可恢复。只读验证结果标记时间与验证范围，不存“永久可写”结论。
4. `state.automation`、交付、Tasks 与对象映射沿用原生命周期；重复点击、断线、重启均先回读原意图，不能另建轮次规避错误。
5. 目标、接收起点、文件规则和本笔身份策略按原边界冻结；预览和回退不改变已启用绑定。
6. `RUNNING / WAITING_REVIEW / FAILED / PAUSED / COMPLETE` 与观测错误分别表达；离线、缺认证、无记录都不能投影为成功。
7. 当前操作和失败步骤可自动展开，用户展开历史、输入、滚动位置不被周期刷新覆盖；窄屏操作条不遮挡内容。

## 5. 验收与验证计划

以下是**实施后的验收要求，不是本轮已执行结果**。新增行为先观察可重复的失败检查，再实现并验证；复用现有精准回归，不为文案复制实现逻辑。

| 场景 | 通过条件 |
|---|---|
| 新用户分别配置两种模式 | 能按目标选模式，知道必要项；前进后仓库长表单收起，当前步骤及主按钮可见 |
| 只填对象页面与 Token / 手动覆盖接口 | 能看到推导值与来源，错误指向具体字段；独立域名与不兼容协议不假称自动适配 |
| 普通校验错误 / Token 请求失败 | 已保存部分明确，不丢普通草稿，不泄露密钥，不重复创建项目 |
| 刷新、关页、重启服务 | 同进程认证仍可用；重启缺密钥时回到原任务补充，不写浏览器存储、配置或历史 |
| 历史 A 到外部后续 20 个提交 | 不误选外部最新为 U0；I0 读取当前内部 HEAD；登记不修改 main |
| README 命名反转与内部目录 | 树选择、继承、半选、分页及不存在路径正确；跳过范围清楚，其他核心文件严格校验 |
| 过程模式含 PR 与无 PR 主干提交 | 一次意图逐笔创建 Issue/候选/PR；无 PR 提交自动纳入，读取失败或多义关联暂停 |
| 人工合入后继续 | 内部具体 PR 链接可用；后台自动核验、按条件关单并回读，再处理下一笔；不要求用户逐步点执行 |
| 共享 Issue 跨笔接收 / 普通关联 | 所需提交未齐不提前关单，普通关联不关闭；界面给出仍缺哪项 |
| 断网、限流、回执丢失、保存失败 | 保留最后可靠状态并提供针对性恢复；远端 Issue/PR 不重复，业务成功与记录失败可区分 |
| 停止后续、内部 HEAD 变化、tag 移动 | 不承诺撤销已发写入；不重置基线或静默更换终点；原任务可追溯 |
| 两个项目不同模式并行 | 配置、认证、草稿、历史隔离；切换不停止后台，延迟响应不串项目 |
| 历史和只读预览 | 当时配置、SHA、对象与时间可回看；缺失明确；预览无远端写入，历史无执行按钮 |
| 宽屏、窄屏、键盘与长列表 | 1440/1024/768/390px 检查主操作、表单与长 tag；错误焦点可达，触控目标足够，刷新不抢焦点、不丢展开 |

自动化在插件目录执行当前 `package.json` 已有命令：`npm test`、`npm run test:browser`、`npm run lint`、`npm run build`，预期均 exit 0；新增旅程须加入浏览器脚本入口。打包资源、安装入口或发布文件范围有变化时追加 `npm run test:package`。`lint` 实际为语法与 Manifest/MCP 检查，不将它误称为格式化；本仓没有 `pnpm check:fix`，不套用其他仓库命令。

补做无提示可用性观察：让未参与实现的人完成首次配置、处理一次认证失败、处理文档差异、找到待审 PR、切换项目和查看一笔历史；记录每次犹豫、走错入口、求助和耗时。目标是每个测试任务均有清楚下一步，且零串项目写入、零误覆盖、零重复对象；用户审核实测体验。配置操作、Git 下载、API 等待和人工审核分开计时，小样本观察不换算“满意度提高百分比”。

验证环境使用隔离仓库及平台接口合同覆盖异常，标明哪些是真实 Git、哪些是平台测试替身。真实内网的 PR 创建、Issue 关联和关单仍需部署后的实际结果验收，不用测试替身冒充通过。实施通过后更新原正式试用入口并回读健康状态和原项目历史，不启动 demo 服务。
